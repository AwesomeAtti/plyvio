Where the Library switcher and the collapse control go

The switcher is a scope selector: it names which database the Library Workspace is showing, and its list comes from the Databases configured in Settings (§3.4.8). In the prototype it would be presentational only — the same dataset stays on screen whichever entry is picked, and search is untouched.

Adding it creates a competition the 40px sidebar header has not had before: it now has both a name to show and a control to hold. Four placements below, then three for the collapsed rail.

Accepted 4 Sep — wireframe (G1) and prototype (G2) approved · specification (G3) pending

This wireframe is accepted and the control is built. It is not yet in the specification, so it has no section number and must not claim one — §3.2.3.9 is Sidebar Resizing. G3 is a separate approval.

The approvals here are retrospective: the three gates were defined while this work was already under way. That is recorded as an exception in STATUS.md, not a precedent.

Option A — the switcher fills the Sidebar header with the collapse control trailing it. It matches the closest structural analogues (Notion, Linear: a switcher in the header of a collapsible sidebar, in an app with no window-spanning toolbar), and the name budget that argued against it stopped mattering once two other things were settled.

The switcher carries no icon. A Library is a database file — one object, two words — so a glyph beside the name in a panel that is unambiguously the library would be a second name for the same thing. That returns 24px, taking the name budget from 122px to 146px.

Names middle-truncate, with the full name on hover and in the menu. End truncation renders "Chessgui Reference 2026" and "…2025" as the same string; see the note in LS-01.

Also settled: the pinned tab keeps its fixed "Library" label, and Settings keeps the word "Databases". Still open: whether the "Library" group heading survives beneath a header that now names the library.
