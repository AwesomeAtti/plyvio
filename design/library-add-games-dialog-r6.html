Add Games, at 600 × 400

The dialog as built is 820 × 600 — larger than the 700 × 430 drawn in r5. At the 800 × 600 window floor it hits its max-width and max-height and covers the Library from edge to edge.

This revision draws it at 600 × 400 and goes through what each tab loses. The anatomy, the tab order, the band heights and every control stay as r5 left them. Only the source band shrinks. A few things stop fitting there, and one turns out to be broken already.

Fixed at 600 × 400, not fitted to the content

Every tab gets the same box, so switching File · Online · Paste never makes the dialog jump, and the Cancel and Add Games buttons stay put. The fixed bands keep r5's heights, which leaves only the source band to shrink — from 364 px to 164 px. Everything below is about what fits in 164 px.

2 · The three tabs in 164 px

3 · The menus in the option rows — broken already

Measuring for the resize turned up a bug that is in the build today. The option rows are pinned to the bottom of the dialog, so the gap between the Tags field and the dialog's bottom edge is 89 px at any height, 600 as well as 400. The Tags menu opens downward and needs 115 px. .dlg is overflow: hidden, so the last tag is cut off. On the Collections row the gap is 49 px. The resize doesn't cause this, but the fix belongs in the same change.

Suggested Open upward in the option band

A placement="up" prop on SelectField and TokenField, set on the four controls in the option rows, plus a max-height of eight rows with scrolling.

The menu stays inside the dialog, so it can't be clipped by the dialog or by the workspace edge at the window floor.

Alternative Let menus hang outside the dialog

Remove overflow: hidden from .dlg (rounding the header and footer corners instead), and menus drop down over the scrim.

At the window floor there's about 80 px below the dialog, so a long tag list would then be clipped by the workspace. That moves the problem somewhere else instead of fixing it.

Not changing

  • The three bands and their fixed heights: header 38 · tabs 34 · option rows 40 · commit 42.

  • The Online tab's single line, and the widths of its Source (126 px) and From (112 px) fields.
  • Import Report (580 × 440) is already about this size and isn't part of this revision.

What changed in code

  • AddGamesDialog.svelte — .dlg is 600px × 400px, still capped by max-width/max-height: 100%.
  • D‑1 — the .fh and .ftot rows and their styles are gone. add.sourceCol is removed from all three locales.
  • D‑2 — the subscribed list, its objects import and the .subs styles are gone. add.subscribed is removed from all three locales.
  • D‑3 — SelectField and TokenField take placement="up", set on Add to, Duplicates, Tags and Collections. Both menus scroll past eight entries.
  • Tests: nothing in addGames.test.js refers to these rows. jsdom has no layout engine, so the size and the menu direction were checked by rendering the component in a browser.

Also found while measuring — not part of this revision
